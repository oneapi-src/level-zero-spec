zesInfoLogDecoderContextCreateExt#

Added in version 1.21

ZE_APIEXPORT ze_result_t ZE_APICALL zesInfoLogDecoderContextCreateExt(zes_info_log_handle_t hInfoLog, zes_info_log_decoder_context_handle_t *phDecoderContext)#

Create a decoder context for an info log.

  • A decoder context decodes the records returned by zesInfoLogInstanceReadWithMetadataExt or by zesInfoLogInstancePeekWithMetadataExt into named fields, which the application reads one at a time using zesInfoLogDecoderContextReadFieldExt.

  • Any number of decoder contexts may exist for one info log.

  • The application may call this function from simultaneous threads.

Parameters:

  • hInfoLog – [in] handle of the info log that the records are read from

  • phDecoderContext – [out] handle of the decoder context that was created.

Returns:

  • ZE_RESULT_SUCCESS

  • ZE_RESULT_ERROR_UNINITIALIZED

  • ZE_RESULT_ERROR_DEVICE_LOST

  • ZE_RESULT_ERROR_OUT_OF_HOST_MEMORY

  • ZE_RESULT_ERROR_OUT_OF_DEVICE_MEMORY

  • ZE_RESULT_ERROR_INVALID_ARGUMENT

  • ZE_RESULT_ERROR_UNSUPPORTED_FEATURE

  • ZE_RESULT_ERROR_DEPENDENCY_UNAVAILABLE

  • ZE_RESULT_ERROR_INSUFFICIENT_PERMISSIONS

  • ZE_RESULT_ERROR_NOT_AVAILABLE

  • ZE_RESULT_ERROR_DEVICE_REQUIRES_RESET

  • ZE_RESULT_ERROR_DEVICE_IN_LOW_POWER_STATE

  • ZE_RESULT_ERROR_UNKNOWN

  • ZE_RESULT_ERROR_INVALID_NULL_HANDLE

    • nullptr == hInfoLog

  • ZE_RESULT_ERROR_INVALID_NULL_POINTER

    • nullptr == phDecoderContext

zesInfoLogDecoderContextGetFieldInfoExt#

Added in version 1.21

ZE_APIEXPORT ze_result_t ZE_APICALL zesInfoLogDecoderContextGetFieldInfoExt(zes_info_log_decoder_context_handle_t hDecoderContext, uint32_t *pCount, zes_info_log_decodable_field_info_ext_t *pFieldInfos)#

Get the fields that a decoder context can decode from an info log record.

  • The application should first call this function with pCount pointing to a value of zero to retrieve the number of fields that can be decoded.

  • A call in which *pCount is greater than zero and pFieldInfos is nullptr shall report the number of fields and shall not write any descriptor, as a call with a count of zero does.

  • The application may call this function from simultaneous threads.

Parameters:

  • hDecoderContext – [in] handle of the decoder context

  • pCount – [in,out] pointer to the number of fields that can be decoded. if count is zero, then the driver shall update the value with the total number of fields that can be decoded and shall not return any descriptor. if count is greater than the number of fields that can be decoded, then the driver shall update the value with the correct number of fields.

  • pFieldInfos – [in,out][optional][range(0, *pCount)] array of field descriptions, one element per field. if count is less than the number of fields that can be decoded, then the driver shall only retrieve that number of descriptors.

Returns:

  • ZE_RESULT_SUCCESS

  • ZE_RESULT_ERROR_UNINITIALIZED

  • ZE_RESULT_ERROR_DEVICE_LOST

  • ZE_RESULT_ERROR_OUT_OF_HOST_MEMORY

  • ZE_RESULT_ERROR_OUT_OF_DEVICE_MEMORY

  • ZE_RESULT_ERROR_INVALID_ARGUMENT

  • ZE_RESULT_ERROR_UNSUPPORTED_FEATURE

  • ZE_RESULT_ERROR_DEPENDENCY_UNAVAILABLE

  • ZE_RESULT_ERROR_INSUFFICIENT_PERMISSIONS

  • ZE_RESULT_ERROR_NOT_AVAILABLE

  • ZE_RESULT_ERROR_DEVICE_REQUIRES_RESET

  • recordCount – [in] number of records in the batch, as returned in *pRecordCount by the read or peek call

  • pDescriptors – [in][optional][range(0, recordCount)] array of metadata describing each record, as returned in pDescriptors by the read or peek call

Info Log Decoder Context - Extension Structures#

zes_info_log_decodable_field_info_ext_t#

Added in version 1.21

Used by: zesInfoLogDecoderContextGetFieldInfoExt
struct zes_info_log_decodable_field_info_ext_t#

Description of one field that a decoder context can decode from an info log record.

  • An array of these structures is returned by zesInfoLogDecoderContextGetFieldInfoExt, one element per field.

  • The fields that are reported are a property of the format of the info log, reported in infoLogFormat of zes_info_log_ext_properties_t, and not of a batch of records. Whether a given record carries a given field is reported per record by zesInfoLogDecoderContextReadFieldExt.

  • The application must locate a field by name, and must then use the fieldId, type and requiredBytes that are reported for that name.
